Quick Start

Get up and running in under a minute. Clone, run, done.

1

Clone the repository

Grab the latest version directly from GitHub.

shell
git clone https://github.com/Thaton3gu7/ProjectR.git cd ProjectR
2

Launch the interactive menu

No installation required — runs directly from the checkout.

shell
bash main.sh
3

Install the global launcher

Run setup.sh once to get the project command available system-wide.

shell
bash setup.sh # Use from anywhere: project --help project --install=git
Zero Prerequisites

⚡ One-Shot Remote Install

No clone needed. One command — clone, setup, and PATH configuration in a single shot.

curl install
# Full install with a single command curl -fsSL https://raw.githubusercontent.com/Thaton3gu7/ProjectR/master/setup.sh | sh
wget install
wget -qO- https://raw.githubusercontent.com/Thaton3gu7/ProjectR/master/setup.sh | sh

What happens under the hood:

1

Interactive Setup Menu

A TUI menu opens to configure launcher name, install dir, bin dir, and PATH settings before anything is installed.

2

Clone

Uses git clone --depth 1 (or tarball fallback if git isn't available).

3

Launcher + PATH

Creates the executable launcher and updates .bashrc, .zshrc, and .profile automatically.

Headless / scripted installs:

headless mode
# Skip menu, use defaults curl -fsSL .../setup.sh | bash -s -- --no-menu # Custom command name + install dir PROJECTR_COMMAND_NAME=projectr PROJECTR_INSTALL_DIR=~/.projectr \ curl -fsSL .../setup.sh | bash -s -- --no-menu
Configuration

🔧 Setup & Launcher

Install the global project command for any-directory use.

Interactive (recommended)
bash setup.sh
With flags
# Defaults, no menu bash setup.sh --no-menu # Custom name + location bash setup.sh --no-menu --command=projectr --install-dir="$HOME/.projectr" # Auto-update PATH in shell rc files bash setup.sh --no-menu --add-path

After setup:

launcher commands

Reproducible

◎ Profiles & Config as Code

Export, share, and replay your exact terminal setup across any machine.

profile workflow
# Export your current installed tools project --export # Import on another machine project --import=projectr_profile_2026-05-30.txt

YAML config:

projectr.yml
tools: - git - curl - tmux - neovim - fzf - ripgrep

TOML config:

projectr.toml
tools = ["git", "curl", "tmux", "neovim"]
install from profile
project install --profile=projectr.yml
Extensible

◆ Plugin System

Add custom tools without editing the core registry. Drop a TOML file and you're done.

tools.d/mytool.toml
cmd = "ripgrep" pkg = "ripgrep" name = "Ripgrep" desc = "Fast recursive search" type = "pkg" extra = "-" category = "Dev"

Plugin rules:

  • ✓ Can append tool entries to the registry
  • ✓ Must use supported TOML keys only
  • ✗ Cannot use special type or executable hooks
  • ✗ Cannot shadow core variables or SCRIPT_DIR
  • ✗ Cannot install signal traps or define shell functions

Help

? FAQ

Does the installed copy auto-update?▼
No. ProjectR does not auto-sync on every run. Use project --self-update or rerun bash setup.sh from your checkout to refresh.
What if ~/.local doesn't exist?▼
setup.sh creates the needed directories with mkdir -p. If the normal location fails, it falls back to ~/.projectr-app/projectr and ~/bin.
Does the one-shot install need git?▼
Ideally yes — it uses git clone --depth 1 for the fastest setup. But if git isn't available, it falls back to downloading a tarball via curl/wget.
Does it work on Termux (Android)?▼
Yes. ProjectR is designed to work in minimal environments including Termux. It auto-detects pkg as the package manager and handles Android-specific paths.
Is it safe to pipe curl into sh?▼
The setup script only clones the public GitHub repo and creates a launcher. No package installs, no system file modification, no sudo required. You can inspect it first: curl -fsSL .../setup.sh | less.
How do I add my own tools?▼
Either add entries to lib/data/tools.sh using the pipe-delimited format, or drop TOML files into tools.d/ for a non-invasive plugin approach.
What Bash version is required?▼
Bash 4+ is recommended. Scoped namerefs require Bash 4.3+, but ProjectR includes eval-based fallbacks for older versions — useful on macOS which ships with Bash 3.2.
Can I use ProjectR in CI/CD pipelines?▼
Absolutely. Use --install=<name>, --dry-run --json, audit --strict, and profile imports for fully non-interactive CI usage.
