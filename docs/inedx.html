Quick Start

Get up and running with ProjectR in under a minute. Clone, run, enjoy.

1

Clone the repository

Grab the latest version from GitHub.

bash
git clone https://github.com/Thaton3gu7/ProjectR.git cd ProjectR
2

Run ProjectR directly

Launch the interactive menu — no installation required.

bash
bash main.sh
3

Or install the global launcher

Run setup.sh once to install the project command system-wide.

bash
bash setup.sh # Now use from anywhere: project project --help project --install=git
Zero Prerequisites

⚡ One-Shot Remote Install

No need to clone first. A single curl command clones the repo, sets up the launcher, and adds it to your PATH — all in one shot.

One-Shot Install via curl
# Install ProjectR with a single command curl -fsSL https://raw.githubusercontent.com/Thaton3gu7/ProjectR/master/setup.sh | sh
Or with wget
wget -qO- https://raw.githubusercontent.com/Thaton3gu7/ProjectR/master/setup.sh | sh

What happens behind the scenes:

1

Detection

The script detects it's running in remote/piped mode (no local checkout found).

2

Clone

Uses git clone --depth 1 (or downloads a tarball if git isn't available) into ~/.local/share/projectr.

3

Launcher

Creates an executable project command in ~/.local/bin/.

4

PATH

Automatically adds ~/.local/bin to your .bashrc, .zshrc, and .profile.

Customize the remote install:

Environment overrides
# Custom command name PROJECTR_COMMAND_NAME=projectr curl -fsSL .../setup.sh | sh # Custom install location PROJECTR_INSTALL_DIR=~/.projectr curl -fsSL .../setup.sh | sh # Custom repo (forks, private mirrors) PROJECTR_REPO_URL=https://github.com/you/ProjectR.git curl -fsSL .../setup.sh | sh
Configuration

🔧 Setup & Launcher

Install the global project command for use from any directory.

Setup with options
# Default setup bash setup.sh # Custom command name bash setup.sh --command=projectr # Custom install directory bash setup.sh --install-dir="$HOME/.projectr" # Custom bin directory bash setup.sh --bin-dir="$HOME/bin" # Auto-add to PATH in shell rc files bash setup.sh --add-path

After setup:

Launcher commands
project # Launch interactive menu project --help # Show all flags project --install=git # Install a tool non-interactively project --self-update # Pull & refresh from source checkout project --setup-info # Show install paths

Fallback directories:

If ~/.local/share can't be created, setup falls back to ~/.projectr-app/projectr.
If ~/.local/bin can't be created, it falls back to ~/bin.
If both fail, setup exits with an error — no half-installed state.

Extensible

🧩 Plugin System

Add custom tools without editing the core registry.

Drop TOML files into the tools.d/ directory. ProjectR loads them automatically on startup. Plugins are treated as data-only — no executable hooks or shell code allowed for security.

tools.d/ripgrep.toml
cmd = "ripgrep" pkg = "ripgrep" name = "Ripgrep" desc = "Fast recursive search" type = "pkg" extra = "-" category = "Dev"

Plugin rules:

  • ✅ Can append tool entries to the registry
  • ✅ Must be valid TOML with supported keys only
  • 🚫 Cannot define special types or executable hooks
  • 🚫 Cannot mutate core variables or SCRIPT_DIR
  • 🚫 Cannot install signal traps or define shell functions

Help

❓ Frequently Asked Questions

Does the installed copy auto-update? ▼
No. ProjectR does not auto-sync on every run to avoid surprises. Use project --self-update or rerun bash setup.sh from your checkout to refresh.
What if ~/.local doesn't exist? ▼
setup.sh creates the needed directories with mkdir -p. If normal locations fail, it falls back to ~/.projectr-app/projectr and ~/bin.
Does the one-shot curl install need git? ▼
Ideally yes — it uses git clone --depth 1 for the fastest setup. But if git isn't available, it falls back to downloading a tarball via curl/wget.
Can I use ProjectR on Termux (Android)? ▼
Yes! ProjectR is designed to work in minimal environments including Termux. It auto-detects pkg as the package manager.
Is it safe to pipe curl into sh? ▼
The setup script only clones the public GitHub repo and creates a launcher script. It does not run any package installs, modify system files, or require sudo. You can inspect the script first with curl -fsSL .../setup.sh | less.
How do I add my own tools? ▼
Either add entries to lib/data/tools.sh using the pipe-delimited format, or drop TOML files into tools.d/ for a non-invasive plugin approach.
What Bash version is required? ▼
Bash 4+ is recommended. Some features like scoped namerefs require Bash 4.3+, but ProjectR includes eval-based fallbacks for older versions.
Can I use ProjectR in CI/CD pipelines? ▼
Absolutely. Use flags like --install=<name>, --dry-run --json, audit --strict, and profile imports for fully non-interactive CI usage.
